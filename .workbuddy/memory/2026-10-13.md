# 2026-10-13 工作日志

## 跨平台兼容：@人解析改造（QQ 官方 Bot 场景）

### 背景
用户反馈：接入 **QQ 官方 Bot** 后「@人」相关功能失效，且回复消息时不引用对方原消息。

### 诊断结论（区分「平台限制」与「插件缺陷」）
查 AstrBot 官方平台适配矩阵（`docs.astrbot.app/dev/star/plugin.html`）：

| 平台 | At | Plain | Image | Record | Video | Reply | 主动消息 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| QQ 个人号(aiocqhttp) | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **QQ 官方接口** | ❌ | ✅ | ✅ | ❌ | ❌ | **❌** | ❌ |

- **平台硬限制（插件无法修复）**：QQ 官方接口 **At=❌、Reply=❌**
  → 回复时无法 @发送者、无法引用原消息，均为平台侧能力缺失，非插件 bug。
  注：QQ 官方 Bot 反而**强制要求**发送消息时带 At，与个人号行为相反。
- **插件真实缺陷（可修）**：4 处 @ 解析硬编码 `isinstance(comp, At)` + `comp.qq`，
  而 QQ 官方 Bot **接收侧不产出 At 组件**，遍历消息链必然取不到目标。

### 4 处改造点（已全部统一）
| 位置 | 函数 |
|---|---|
| `utils.py` `parse_target_user_id` | 管理员指令通用解析 |
| `handlers/social_handlers.py` | 偷鱼 `steal_fish` |
| `handlers/social_handlers.py` | 电鱼 `electric_fish` |
| `handlers/inventory_handlers.py` | 偷看鱼塘 `peek_pond` |

### 实现
新增 `utils.find_mentioned_user_id(event)`（+ 私有 `_extract_at_user_id`），优先级：
1. 消息链 At 组件，字段名依次尝试 **`qq` / `user_id` / `uid` / `id`**（不再只认 `qq`）；
2. 自动排除机器人自身（`!= message_obj.self_id`）；
3. 回退正则解析消息文本 @ 标记：`[CQ:at,qq=xxx]` / `<@!xxx>` / `<@xxx>`（QQ 官方 Bot 实际 @ 形态）；
4. 仍无则交由调用方走**文本参数兜底**（`/偷鱼 12345`）。

`@` 优先级仍高于文本参数（保持原语义）。清理：两个 handler 中不再使用的 `At` 导入与
`peek_pond` 里已失效的 `message_obj` 局部变量。

### 验证
`/tmp/verify_at_compat.py`（最小 AstrBot 桩，无需完整 FishingPlugin）**9 项全绿**：
QQ-AT-QQ-FIELD / AT-USERID-FIELD（改造前会失败的 user_id 字段）/ QQOFFICIAL-TEXT-AT（`<@!xxx>`）/
AT-TEXT-ALT（`<@xxx>`）/ CQCODE-AT / EXCLUDE-SELF / FALLBACK-PLAINTEXT / AT-PRIORITY / NO-TARGET-ERROR。
pyflakes 无 severe；compile OK。

**测试坑**：写「无 @ 走参数兜底」用例时，若复用了仍带 At 组件的事件，@ 会优先命中导致断言失败——
这是**设计预期**（@ 优先），不是 bug，需用真正无 @ 的事件构造用例。

### 未改动（平台限制，改造无意义）
- 发送侧 At / Reply：受平台限制，即使插件构造了组件，QQ 官方 Bot 也不会渲染。
- 两处 `event.get_group_id()`（`red_packet_handlers._get_group_session_id`、
  `sicbo_handlers._get_game_session_id`）已有 `if group_id:` 兜底，频道/私聊下返回 None 走 else 分支，
  **不会崩溃**，无需改动。

## 修正：QQ 官方 Bot 接入方式 + @人解析真正根因（读取 AstrBot 适配器源码）

用户新需求：「原来接 NapCat，现在用官方 Bot，帮我改成官方 Bot 接入方式」。
重新读取 AstrBot `qq_official` 适配器源码（`astrbot/core/platform/sources/qqofficial/qqofficial_platform_adapter.py`）
后发现**此前 2026-10-13 上半段的诊断有误**，更正如下：

### 适配器真实行为（关键）
- `on_group_at_message_create`：对群消息 `abm.sender = MessageMember(message.author.member_openid, "")`，
  `abm.group_id = message.group_openid`，`abm.self_id = "unknown_selfid"`，
  **消息链写死 `msg.append(At(qq="qq_official"))` + `Plain(content)`**——即注入一个**哨兵 At** 表示「被 @」，
  真正的目标用户只以 `<@!openid>` / `<@openid>` **文本**出现在 `content` 里（openid 为**字母数字串**，非纯数字）。
- 频道/DirectMessage 分支会把 `<@!self_id>` 从 content 剥离，`self_id` 设为真实 openid。
- **结论**：QQ 官方 Bot 下 At 段「接收侧不产出真实 At」为真，但 AstrBot 用哨兵 + 文本兜底，
  **@人完全可被插件解析**——此前「@人不可用、改用写用户ID」的结论是错的。

### 此前 a68e64d 修复的缺陷（实际仍坏）
`find_mentioned_user_id` 当时：①At 循环未跳过哨兵 `qq_official` → 直接返回字面量 `"qq_official"`；
②文本正则只匹配 `[0-9]+` → 匹配不到字母数字 openid。两种情况下 @目标指令全部失效/误命中。

### 真正修复（utils.py，已验证）
- At 循环：遇 `qq=="qq_official"` 记 `saw_qq_official_sentinel` 并跳过，且排除 `self_id`；
- 文本正则扩为 `<@!([A-Za-z0-9_-]+)>` / `<@([A-Za-z0-9_-]+)>`（覆盖 openid）+ 保留 `[CQ:at,qq=数字]`；
- 官方 Bot 群消息约定「@机器人 @目标」顺序 → 取**最后一个** @ 为目标；仅 1 个且 `self_id` 为空（群占位）视为无目标；
  频道/私聊 `self_id` 为真实 openid → 排除 bot 后剩目标即返回。
- 验证 `/tmp/verify_qqofficial_mention.py`：qo群带目标→TARGET✅ / qo群仅bot→None✅ / qo频道→TARGET✅ /
  NapCat At→QQ✅ / NapCat CQ文本→QQ✅ / 无@→None✅（6/7，余 1 为「@目标写在bot前」已知边界）。
- pyflakes：仅 `aiohttp` 未用导入 + 488 行 f-string 无占位（均属项目容忍项，非本次引入）。

### 接入方式（框架层，非插件代码）
平台切换在 AstrBot 管理面板：机器人 → +创建 → **QQ 官方机器人(WebSocket)** → 填 appid/secret（或扫码一键创建）
→ **务必勾 `enable_group_c2c`**（否则收不到群消息，本插件群游核心）→ QQ开放平台加 IP 白名单 → 群设置开
「获取群内全部消息」+「机器人主动发言」。插件本身不需改配置（无平台字段）。

### ⚠️ 账号体系迁移（重要，用户必须知道）
官方 Bot 下 `get_sender_id()` 返回 **openid** 而非 NapCat 的纯数字 QQ 号 → 旧 `fish.db`（存 QQ 号）全部查不到，
玩家会显示「未注册」。无 QQ#↔openid 映射，无法自动迁移 → 需**清空 fish.db 重新注册**（停插件→删 fish.db→重启）。
指令目标请**直接 @人**（已修复），不要写纯数字 QQ（官方 Bot 下非法 openid）。
