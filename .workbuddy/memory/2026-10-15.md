## 修复：Image 构造参数误写 file_path 导致 /状态 崩溃（v2.4.21）

用户报：用 `/状态` 时报 `Image.__init__() missing 1 required positional argument: 'file'`。

### 真因
- v2.4.19 把图片回复写成 `Image(file_path=image_path)`。该 AstrBot 版本的 `Image` 消息组件构造参数是
  **`file`**（本地文件路径），**没有 `file_path` 这个参数**——于是 `file` 必填项缺失 → TypeError。
- 正确参数名应与 `event.image_result(image_path)` 内部构造一致：`Image(file=image_path)`（或位置 `Image(image_path)`）。

### 修复（三个 handler）
- `common_handlers.state` / `inventory_handlers.user_backpack` / `fishing_handlers.pokedex` 的
  `Image(file_path=...)` → `Image(file=...)`。`Plain(mention)` 不受影响。
- 顺手修正 v2.4.19 在 CHANGELOG/README/MEMORY 里误写的 `Image(file_path=path)` 示例为 `Image(file=path)`。

### 验证
- `py_compile` 三个 handler 通过。

### 同步
- README 面板段 v2.4.19 条更正示例；CHANGELOG v2.4.21；metadata.yaml 2.4.20→2.4.21；
  MEMORY.md 版本注 + 「@ 同条消息」chain_result 铁律条补 `Image(file=...)` 说明（含 file_path 误写踩坑）。

## 修正：官方 Bot 群聊 @ 群成员不渲染（v2.4.22）

用户报：按官方文档修正 @，目前 @ 仍不正确（群聊显示成字面 `<@!openid>`）。

### 真因
- 此前 `<@!openid>` 写在**普通文本回复**（`msg_type=0` / `Plain` 组件）里。对照 QQ 官方 Bot 文档：
  @ 群成员**只有在 Markdown(`msg_type=2`) 的 `markdown.content` 中的 `<@!openid>` 才会被平台渲染成可点 @**；
  纯文本里的会被当成普通字符串 —— 这正是「@ 仍不正确」的根因。

### 修复
- `main.py` 新增 4 个方法，统一所有个人回复的 @ 逻辑（复用 `_send_qq_keyboard` 已验证的 botpy 原生 HTTP 通道）：
  - `_send_official_markdown(event, content, at_openid=None, kb=None)`：`msg_type=2` markdown 直发，@ 写进 content 开头。
  - `_official_group_mention_openid(event)`：仅「官方 Bot 且群聊且 sender 非纯数字」返回 openid，其余 None。
  - `send_mention_text(event, text)`：官方 Bot 群聊走 markdown @；否则/失败降级 `plain_result(format_mention_reply(...))`。
  - `send_mention_then_image(event, path)`：官方 Bot 群聊先 markdown @ 再发图片（图片 msg_type=7 无法内嵌 @，平台硬限制拆两条）；否则走 `chain_result([Plain(CQ:at), Image])` 或纯图。
- 调用点改走新 helper：`common_handlers.sign_in`/`state`、`fishing_handlers.fish`/`fish_pokedex`、
  `inventory_handlers.user_backpack`、`main.py::quick_menu`/`quick_select`。NapCat `[CQ:at,qq=...]` 与私聊不变。

### 验证
- `py_compile` 全部改动文件通过；`MarkdownPayload(content=...)` 字段名与已验证的键盘发送一致（本机无 botpy，无法实跑）。

### ⚠️ 待用户实测

  若出现「@ 出了但图没了」= 双被动回复 msg_seq 冲突，需把图片也走 botpy 或调 msg_seq。

## 新规：回复归属必须同一条消息 + 图片改画昵称（v2.4.23）
